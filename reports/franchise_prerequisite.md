# 続編推薦の前提条件チェック

## 問題

MyAnimeListは「1シーズン=1エントリ」でデータを持っており、`animelist.csv`にも
`anime.csv`にもシリーズの繋がり（S1とS2が同じ作品群か）を示す列は無い。この結果、
`will_complete`/`at_risk`が、ユーザーが前作を見ていない続編を推薦してしまう問題が
起きていた。

テストユーザー20人の推薦結果を実際の視聴履歴（`animelist.csv`の全履歴）と突き合わせた
ところ、続編と判定できた推薦候補18件中10件（**55.6%**）で前作が履歴に一切無かった。
特定ユーザーでは推薦された続編5件全てで前作未視聴という極端なケースもあった。
これは仕様論以前に、体験として壊れている状態だった。

## タイトル正規化を却下した理由

Season N / Part N / ローマ数字を除去する正規表現でのグルーピングを最初に検討したが、
有名フランチャイズ10件を目視確認した結果、信頼できないと判断した。

- **銀魂**: 21件中グループ化できたのは**0件**。`Gintama'`/`Gintama°`/`Gintama.`のように
  句読点だけでシーズンを表す命名規則には正規表現が一切対応できない
- **誤結合**: 「Samurai 7」（2004年、七人の侍が由来で"7"はタイトルの一部）が末尾数字の
  除去処理で無関係の別作品「Samurai」と同一グループに誤って結合された
- MAL_IDの大小は公開順と一致しない実例あり（「To Heart 2」がMAL_ID=471、無印
  「To Heart」がMAL_ID=472と逆転）。前後判定にMAL_IDは使えない

## Jikan API `/relations` を却下した理由

認証不要で使えるJikan API v4の`/v4/anime/{id}/relations`を検討したが、登録者数上位10作品
に対して疎通確認したところ**30試行（10作品×最大3回リトライ）すべてが504**だった。
同時に基本エンドポイント`/v4/anime/{id}`は200で正常応答しており、Jikan全体ではなく
`/relations`エンドポイント固有の障害と確認できた。成功率0%はステップ1で定めた停止基準
（5割未満で停止）を大きく下回ったため、この方針は採用しなかった。

## AniListデータセットの採用

Kaggleの`calebmwelsh/anilist-anime-dataset`（AniList GraphQL API由来、257MB）を採用した。
実測結果:

- 総件数: 20,422件
- idMal（MAL_IDとの対応）充足率: 95.1%
- **登録者数上位300作品のidMal突合率: 100%**（300/300）
- SEQUEL/PREQUELエッジをnode.idからidMalへ逆引きできた割合: **92.0%**（ANIME型ノード限定）

上位300作品のカバー率100%は、ステップ1で定めた停止基準（8割未満で方針再検討）を
大きく上回ったため採用を決定した。

`scripts/build_relations.py`でSEQUEL/PREQUEL・node.type==ANIMEのエッジのみを抽出し、
`data/processed/anime_relations.json`（5,710作品分）を生成する。SIDE_STORY/SUMMARY/
ALTERNATIVE/SPIN_OFF/PARENT/ADAPTATIONは対象外。検証として、この抽出ロジックで
銀魂の全チェーン（Gintama→Gintama'→Gintama°→Gintama.→…→The Final）が単一の
`franchise_root`に正しく統合されること、Fate（stay night/Zero/kaleid liner/Grand Order等）
が独立系列として適切に分かれたままであること、鋼の錬金術師（2003年版とBrotherhood、
ALTERNATIVE関係）が非連結のままであることを目視確認済み。

## Members比率ルールの導入理由と閾値の検証経緯

前提条件チェックをそのまま適用すると、「進撃の巨人1期」の直接prequelがAniList上で
配信専用OVA「悔いなき選択」になっているため、「OVAを見ていない人にTVシリーズ1期を
推薦しない」という誤った除外が起きる。1期は誰もがまず見る入り口であり、OVAはそれを
補完するサイドコンテンツに過ぎない。

そこで「対象作品のMembers（登録者数）がprequelのMembersのX倍以上なら、対象作品自体を
実質的な入り口とみなし除外しない」というルールを追加し、Xを次の順で検証した。

| X | 上位300作品での救済件数 |
|---|---|
| 5 | 16件 |
| 6 | 未精査（採用見送り） |
| 7 | 14件 |
| **7.8369**（進撃の巨人1期が救済される最小の実測値） | 14件 |
| 8 | 12件 |
| 10（当初案） | 7件 |

- **X=10**: 最も分かりやすい動機となった進撃の巨人1期の実測倍率が7.8369倍のため、
  救済できなかった
- **X=8**: 「進撃を含む」と見込んで選んだが、実測は7.8369倍で8倍にわずかに届かず、
  やはり救済できなかった（丸めた「7.8倍」という表現が誤解を招いた）
- **X=7**: 進撃の巨人1期を含む最小の整数。X=8との差分は2件のみで、内訳は
  「進撃の巨人1期 vs 悔いなき選択OVA」「Another vs Another: The Other - Inga」。
  両方とも「OVAは本編を補完するサイドコンテンツで視聴の前提条件ではない」という
  同じ構造であることを確認した上で採用した
- **X=6以下**: その差分の中身を未確認のため見送り。閾値を下げすぎると、本当に
  前提知識が必要な続編まで誤って救済してしまうリスクがある

**X=7で救済される14件**（上位300作品）: One Piece / Jujutsu Kaisen（前作が2020年
snapshot後の新規作品のためMembers=0扱いで自動救済）、進撃の巨人1期、One Punch Man、
Tokyo Ghoul、四月は君の嘘、Another、Guilty Crown、境界の彼方、黒子のバスケ、Hellsing
Ultimate、GTO、Free!、神のみぞ知るセカイ。

`PREREQUISITE_MEMBERS_RATIO = 7`として`api/services/predict.py`に実装した。

## 検証結果

テストユーザー20人（`user_splits.json`の`test`分割先頭20人）で再測定した。

| | 修正前（推定） | 修正後 |
|---|---|---|
| 前作未視聴の続編が推薦される割合 | 55.6%（18件中10件） | **12.5%**（8件中1件） |
| at_risk合計（20人分） | 41件 | 40件（-1） |
| will_complete合計（20人分） | 200件 | 200件（±0、全員上限維持） |

候補数への影響はほぼ無く、除外によって推薦の質が大きく損なわれることはなかった。

残る1件（宇宙戦艦ヤマト2199）は、`anime_relations.json`に**prequelエントリが存在しない**
ため通過している。AniList側で1974年版とはSEQUEL/PREQUELではなくALTERNATIVE（リブート）
関係に分類されているためで、「relationsが取得できていない作品は除外対象としない」という
設計判断通りの正しい通過であり、実装の不具合ではない。リブート作品は前作を知らなくても
単体で視聴できるものが多く、この挙動は許容範囲と考えられる。
