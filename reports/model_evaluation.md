# Phase 2 モデル評価レポート（修正版）

`docs/requirements.md` 5章に基づく予測モデルの評価結果。分析ノートブック: [`notebooks/02_model.ipynb`](../notebooks/02_model.ipynb)（実行済み・エラーなし）。

## v1からの修正点

1. **PR-AUCを離脱=正例で再計算**（最優先）。旧版は完走（多数派）を正例としており、ベースラインPR-AUCが0.90前後と最初から高すぎて識別力が見えなかった
2. **埋め込みの新作パス検証を追加**。`anime_avg_completion_rate` を除外した特徴量セットで埋め込みあり/なしを比較し、2021年以降の新作判定（UI仕様書5.6, `is_estimated: true`）の精度見込みを検証
3. **人気順トップ20との重複比較を再設計**。旧版は「ユーザーが既に見た作品」内での並べ替えになっており、UI仕様書4.8（未視聴作品の推薦画面）と対応していなかった。テストユーザーごとに未回答の作品200本を候補として抽出し直した

## 定義の変更: 主定義を定義A（離脱=4のみ）に変更

- 学習ラベル: 定義A（離脱=4のみ）。プロファイル入力も定義A（保留は使わない）
- UIは3ボタンのまま変更しない。ユーザーの「途中で止まった」をMALの離脱(4)相当の意思表示として扱う。MALの保留(3)は記録習慣の差（Phase 1で確認した相関-0.77）を含むため学習から除外する
- **`data/dropout_curves.json` / `data/question_pool.json` は定義Bのまま維持**（脱落曲線は「どこで人が止まるか」の集計であり、ラベル定義とは目的が異なるため再生成していない）
- 根拠は前バージョンのレポート（記録習慣の検証: (a)定義Aのみ AUC=0.838 > (b)定義B AUC=0.831）で確立済み

## 実験設定

- サンプル: 15,000ユーザー（Phase 0と同じ2パス方式）。分割は user_id 単位で 訓練70%(10,500人) / 検証15%(2,250人) / テスト15%(2,250人)
- `anime_avg_completion_rate`（定義A版）は訓練ユーザーのみから算出
- 入力制限シミュレーション: question_pool内の回答（定義A該当のみ）をランダム順列にし、先頭30本を入力候補、残り＋pool外の回答（最大40件）を評価対象として固定。N=3/5/10/20/30は入力候補の先頭何本を使うかだけを変える
- モデル: LightGBM、**正例=離脱**（`label_dropped`）。評価指標は AUC / PR-AUC のみ
- 埋め込み: `intfloat/multilingual-e5-small`（`data/processed/` にキャッシュして再利用）

## 1. 評価表【必須・正例=離脱】（N=20基準）

**ベースライン正例率（テストデータの離脱率）: 5.56%**

| | AUC | PR-AUC |
|---|---|---|
| ランダム | 0.497 | 0.055 |
| 人気順（登録者数） | 0.526 | 0.060 |
| 作品の平均完走率のみ | 0.772 | 0.223 |
| ＋ユーザー特徴（耐久話数・ジャンル） | 0.837 | 0.328 |
| ＋埋め込み類似度（完走ベクトルのみ） | 0.838 | 0.323 |
| ＋離脱ベクトル | 0.838 | 0.325 |

正例=離脱で見ると、ランダムのPR-AUCは正例率とほぼ一致（0.055≒0.056、妥当性の確認になる）。**人気順のPR-AUC 0.060はランダムをわずかに上回るのみ**であり、「人気度は完走予測にほとんど情報を持たない」という主張がより明確になった。作品の平均完走率のみでPR-AUCが0.223（ランダム比約4倍）に跳ね上がり、ユーザー特徴の追加でさらに0.328まで伸びる。**埋め込み特徴量（完走・離脱ベクトル）はPR-AUCをほぼ動かさない**（0.328→0.323→0.325、いずれも誤差の範囲）。この点は旧版と同じ結論だが、今回の指標でより明確に確認された。

## 2. 追加分析① 入力本数 × 精度の曲線

| 入力本数 | AUC | PR-AUC |
|---|---|---|
| 3本 | 0.797 | 0.260 |
| 5本 | 0.808 | 0.281 |
| 10本 | 0.828 | 0.309 |
| 20本 | 0.838 | 0.325 |
| 30本 | 0.841 | 0.332 |

PR-AUCで見ても20本前後から明確に頭打ちになる（20→30本の伸びはAUCで+0.003、PR-AUCで+0.006）。UI仕様書の「10本推奨・20本で精度：高・20本超は追加を促さない」という設計と整合する。

## 3. 追加分析② 入力種別ごとの寄与

| 入力種別 | AUC | PR-AUC |
|---|---|---|
| 「好き」のみ | 0.780 | 0.233 |
| ＋「完走」 | 0.778 | 0.230 |
| ＋「途中で止まった」 | 0.838 | 0.325 |

「好き」と「完走」の区別はPR-AUCでもほぼ差がない（0.233→0.230、むしろ僅かに低下）。一方「途中で止まった」（＝定義Aの離脱シグナル）の追加でPR-AUCが+0.095と大きく改善する。**離脱シグナルの収集は精度上必須であり、好き/完走の粒度分けは精度の観点では正当化されない**という結論は旧版から変わらない。

## 4. 追加分析③ 人気順トップ20と個人最適トップ20の重複件数（再設計版）

**修正点**: 候補を「ユーザーが既に見た作品」ではなく、**未回答の作品200本**（登録者数上位3,000作品からランダム抽出）に変更した。これによりUI仕様書4.8（人気順との比較＝未視聴作品の推薦）の実際の使われ方に対応する評価になった。

- **評価ユーザー数: 2,158人**
- **重複件数: 平均 0.86 / 20（中央値1.0）**
- 分布: 0件が927人、1件が777人、2件以上は454人のみ

旧版（重複平均9.92/20）から一変し、**ほとんどのユーザーで人気順トップ20と個人最適トップ20が重ならない**という強い結果が得られた。旧版の候補集合（ユーザーが既に視聴した作品）はもともと人気作に偏っており、両ランキングの土台が似ていたために重複が過大評価されていた。未視聴作品という正しい母集団で見ると、「人気順とは全く異なる個人最適化がなされている」というサービスの主張がより強く裏付けられる。

## 5. 追加分析④ 理論上限の見積もりと達成率の議論

- 完走 3,138,037件 / 離脱(定義A) 202,469件 / 保留 170,045件（学習には不使用）
- N=20→30のAUC改善幅は+0.003、PR-AUC改善幅は+0.006と、いずれも小さく頭打ちが観測された

N=30まで入力を増やしても伸びがほぼ止まっていることから、「作品属性・ユーザー履歴・埋め込み類似度」というこの特徴量ファミリーの中で説明できる情報をほぼ使い切っていると考えられる。現在のAUC 0.84 / PR-AUC 0.33前後は、この特徴量ファミリー内での実質的な上限に近い。これを超えるには、多忙・体調・視聴環境の変化といった本データセットに存在しない外部要因の情報が必要になる。

## 6. 埋め込みの新作パス検証（コールドスタート）【新規】

2021年以降の新作は `anime_avg_completion_rate`（過去の視聴実績）を持たない。この状況を模し、`anime_avg_completion_rate` を除外した特徴量セットで埋め込みの効果を検証した。

| 特徴量セット | AUC | PR-AUC |
|---|---|---|
| anime_avg除外・埋め込みなし | 0.835 | 0.318 |
| anime_avg除外・埋め込みあり | 0.835 | 0.318 |
| （参考）anime_avgあり・フルモデル | 0.838 | 0.325 |

**埋め込みによる回復幅: -0.0002（実質ゼロ）。anime_avg除外による損失は-0.0025とごく小さい。**

### 解釈と示唆

2つの重要な発見があった。

1. **anime_avgを除いても精度はほとんど落ちない**（0.838→0.835）。ジャンル・話数・ユーザー特徴だけで、作品ごとの実績データが無くてもかなりの精度を維持できる。これは新作判定にとって朗報である
2. **しかし、その穴を埋めているのは埋め込みではない**。anime_avgを除いた状態でも埋め込みの追加効果はほぼゼロだった。つまり、新作（`is_estimated: true`）の判定精度は「anime_avgが無いこと」自体はさほど痛くないが、**「あらすじ埋め込みが精度を肩代わりしてくれる」という当初の期待は、この特徴量構成では成立しなかった**

新作判定はジャンル・話数・原作媒体などのメタデータとユーザー側の特徴で妥当な精度（AUC 0.835程度）を維持できる見込みだが、これは「埋め込みのおかげ」ではなく「メタデータで十分」という理由による。UI仕様書5.6の「信頼度：低」表示は、この構造を踏まえると妥当な設計と言える（実際にはメタデータベースの推定であり、埋め込みによる高度な内容理解を伴った推定ではないため）。

## まとめ

- 正例=離脱でPR-AUCを再計算した結果、人気順がほぼ無意味（PR-AUC 0.060 vs ベースライン0.055）であることがより明確になった
- 埋め込み特徴量は、通常時・新作コールドスタート時のいずれにおいても、追加の精度向上にほぼ寄与しなかった。これは要件定義書5.4の設計方針（埋め込み類似度を「本命」とする）に反する結果であり、正直に報告する
- 人気順との重複比較を正しい母集団（未視聴作品）で再計算した結果、重複はわずか0.86/20となり、個人最適化の効果がより強く実証された
- 入力本数は20本前後で頭打ち。「好き/完走」の区別は精度に寄与しない
- **主定義を定義Aに変更した。UIの3ボタン設計は変更せず、学習データの扱いのみを変更する（「途中で止まった」→MAL離脱(4)相当として学習、MAL保留(3)は学習から除外）。Phase 1成果物（脱落曲線・質問プール）は定義Bのまま維持する**

**Phase 3（API実装）にはまだ着手していない。**
