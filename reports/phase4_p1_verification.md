# Phase 4 P1 実装・動作確認レポート

`docs/ui_spec.md` に基づき、P1スコープ（[C]ブロック1・3・4、[D]単体判定画面の全体）を実装した。
実際にバックエンド（FastAPI, port 8000）とフロントエンド（`vite preview`静的ビルド, port 5173）を
起動し、Playwright制御下の実ブラウザで操作して動作確認した（モックデータは使用していない）。

## 実装したもの

### バックエンドの追加（P1実装に必要だった不足分）

- `AtRiskItem` / `WillCompleteItem` スキーマに `year` / `episodes` / `genres` を追加
  （ブロック3・4のメタ情報行「2013 / 全50話 / 日常・部活」に必要だが、既存レスポンスに
  なかったため追加した）
- `PredictSingleResponse` に `next_recommendations`（UI仕様書5.5「次に完走できる作品」導線）を
  追加。完走率80%以上のとき、話題作に絞らない候補プール（登録者数上位3,000作品、放送中除外）
  から上位3件を返す。80%未満は空配列
- `already_answered` レスポンスに `message` フィールドを実装
  （`この作品は回答済みです（完走）` / `（途中で止まった）` を算出方法込みでバックエンドが生成。
  フロントで文言生成しない方針を単体判定にも適用した）
- `/predict/single` に `response_model` を設定し、2種類のレスポンス形状（判定結果 /
  回答済み）をFastAPI側でも検証するようにした

### [C] ブロック1: 単体判定入力（`SingleJudgmentBlock.tsx`）
最上部にsticky固定。300msデバウンスのインクリメンタル検索、オートコンプリート候補から選択すると
[D]をモーダルで開く。検索0件時は「該当する作品が見つかりませんでした。2020年までの作品が
対象です。」を表示（UI仕様書3.3・7章）。

### [C] ブロック3: 話題作だけど続かないかも（`AtRiskBlock.tsx`）
- 主表示は `relative_risk`（「平均より○倍止まりやすい」）、副表示に完走率＋一般平均
- 理由（`reasons`）はAPIの値をそのまま表示（フロントで文言生成しない）
- 末尾に「※ 作品の評価ではなく、あなたとの相性の話です」を必ず表示（該当作品がある場合）
- `at_risk` が0件の場合はブロックを消さず「今回の候補には、あなたが特に止まりやすそうな
  作品はありませんでした」を表示
- 表示は5件まで

### [C] ブロック4: 完走できる作品（`WillCompleteBlock.tsx`）
10件、順位・完走率・年代/話数/ジャンル・1行の理由（APIの`reason`をそのまま表示）。

### [D] 単体判定画面（`SingleJudgmentModal.tsx`）
UI仕様書5章の全項目を実装。

| 項目 | 対応 |
|---|---|
| 5.1 相対指標を主表示・完走率を副表示 | 実装 |
| 5.2 判定文言（改訂しきい値: 95/88/75/50%） | 実装。断定形は使わない |
| 5.3 あなたの実績（evidence 3件 + insight） | 実装。0件時はブロックごと非表示 |
| 5.4 脱落曲線・insufficient_data時の文言 | 実装（「この作品はデータが少なく、止まりやすい話数を表示できません」に修正） |
| 5.5 完走率80%以上の「次に完走できる作品」 | バックエンド新設 + 実装 |
| 5.6 新作（is_estimated）「推定」表示 | 実装（既存Badges.tsx流用） |
| 5.6b 放送中（is_ongoing）「推定」表示 | 実装（既存Badges.tsx流用） |
| 5.7 信頼度バッジ（必ず表示） | 実装 |
| 判定対象が回答済み | 「この作品は回答済みです（完走）」等をバックエンド生成の`message`で表示、判定は行わない |
| APIエラー | 「一時的に判定できませんでした。時間をおいて再度お試しください」＋再試行ボタン |

表示形式はモーダル（UI仕様書4.3「モーダルまたは展開パネル」の一方を採用）。背景クリックまたは
[×]、Escキーで閉じる。

## エッジケース（UI仕様書7章）の対応状況

| ケース | 対応 |
|---|---|
| 回答5本未満で結果画面に直接アクセス | 入力画面へリダイレクト（P0から継続） |
| 全回答が「完走」（離脱データ0件） | 「途中で止まった作品の情報がないため、精度が限定的です」を表示（新規） |
| 全回答が「途中で止まった」 | 「完走した作品の情報がないため、精度が限定的です」を表示（新規） |
| 検索0件 | 「該当する作品が見つかりませんでした。2020年までの作品が対象です。」（ブロック1でも対応） |
| APIエラー | 再試行ボタン付きで表示 |
| 判定対象が回答済み | 判定を行わず「この作品は回答済みです（完走）」等を表示 |

## 表示の一貫性（P0からの継続確認）

- 平均値ラベルの区別: ブロック2「全作品平均」／ブロック3・単体判定「一般平均」を維持し、
  新規ブロックでも同じ命名を使用
- 脱落曲線の1話グレー表示＋注記: `SingleAnimeDropoutCurve`を変更なく流用しているため
  単体判定モーダルでもそのまま機能することを実機確認
- 話数のバケット表記統一: reasons文言（`全500話。あなたが完走しやすいのは14〜26話です`等）は
  すべてAPI側でバケット表現に統一済み

## 動作確認（実機・実データ、Playwright）

1. 8本「完走」で回答→結果画面: ブロック1（sticky）→ブロック2→ブロック3（0件時メッセージ）→
   ブロック4（10件）→ブロック5の順序で表示されることを確認。エラー0件
2. 8本「途中で止まった」で回答: 「完走した作品の情報がないため、精度が限定的です」を確認。
   ブロック3に実データの`at_risk`5件（ナルト疾風伝・BLEACH・FAIRY TAIL等）が理由3件・
   relative_risk主表示・末尾注記付きで表示されることを確認
3. 「デスノート」で単体判定モーダルを開き、相対指標主表示・有利な要素・あなたの実績3件・
   evidence_insight・脱落曲線（1話グレー）・次に完走できる作品（完走率98%のため表示）を確認
4. 既に回答済みの作品（BLEACH）を検索して判定を開き、「この作品は回答済みです（完走）」が
   判定を行わずに表示されることを確認
5. 「ONE PIECE」（放送中）を判定し、「推定」プレフィックス・信頼度低・
   EstimatedNoteの放送中向け文言・脱落曲線の「データが少なく表示できません」を確認
6. 検索欄に存在しない文字列を入力し、0件メッセージを確認
7. デスクトップ幅（1280px viewport）で横スクロールが発生しないことを確認（`scrollWidth === clientWidth`）
8. 全シナリオを通じてブラウザのコンソール・ページエラーは0件
