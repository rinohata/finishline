# 完走予測サービス 要件定義書

## 0. プロジェクト概要

### 何を作るか
ユーザーが過去に見たアニメを数十本選択するだけで、「この作品を最後まで見られるか」を予測するWebサービス。

### 中心的な主張
既存の推薦システムは「好きになる確率」しか予測しない。本サービスは **「続かない確率（離脱）」** を予測する。人気度ベースの推薦は完走予測に対してほとんど情報を持たないことを、実データで示す。

### 重要な用語規約（厳守）
| 文脈 | 使う語 | 使わない語 |
|---|---|---|
| UI表示 | 完走 / 途中で止まった / 続かない | **切る、切った、脱落、ドロップ** |
| コード・内部 | dropped, churn, 離脱 | - |

UI上の確率表示は **完走率に統一**する。離脱確率と完走確率を画面内で混在させない。

## 3. Phase 0: データ検証（Go/No-Go ゲート）

**このフェーズを完了せずに Phase 1 以降へ進んではならない。**
結果は `reports/phase0_report.md` に数値付きで出力すること。

### 3.1 実施内容

`notebooks/00_data_validation.ipynb` を作成し、以下を算出する。

#### チェック① 離脱率
```python
df.watching_status.value_counts(normalize=True)
```
- **合格: dropped が全体の 5% 以上**
- 3%未満: 不合格。作品を人気上位に絞るなど対策を検討

#### チェック② 話数データの有効率
```python
dropped = df[df.watching_status == 4]
(dropped.watched_episodes > 0).mean()
```
- **合格: 70% 以上**
- これが低いと脱落曲線（本サービスの目玉画面）が作れない

#### チェック③ `watching` の割合
```python
(df.watching_status == 1).mean()
```
- 15%未満: 除外して問題なし
- 30%超: 除外すると大量に消失する。以下の追加分析を行う
  - `watching` かつ `watched_episodes` が総話数の50%未満のものの割合
  - これらを「離脱」に含めた場合／除外した場合の両方で Phase 2 の精度を比較し、レポートに併記する
- **どちらの場合も、採用した定義と除外率を必ずレポートに明記する**

#### チェック④ 個人効果の存在【最重要】
```python
# 作品ごとの平均完走率を算出
anime_avg = completed_flag.groupby('anime_id').mean()
# 各ユーザーの「実際の完走 − その作品の平均完走率」の平均
user_effect = (completed_flag - df.anime_id.map(anime_avg)).groupby(df.user_id).mean()
sigma = user_effect.std()
```
- **合格: 標準偏差 σ > 0.08**
- 0.03未満: 個人化がほぼ効かない。**この場合は実装を止めて設計を再検討する**
- 0.03〜0.08: グレー。レポートに記載し、判断を仰ぐ

### 3.2 Go/No-Go 判定
```
①≥5%  AND  ②≥70%  AND  ④σ>0.08  →  GO
それ以外 → 停止してレポートを提示
```

### 3.3 追加で出力するもの
- `watched_episodes` の異常値件数（総話数超過、負値、欠損）
- ユーザーあたりの登録作品数の分布（中央値、四分位）
- 作品あたりの評価件数の分布
- 完走 / 離脱のクラス比

## 4. Phase 1: 集計層（モデル不要）

**この層は予測ではなく事実の集計。精度問題が存在しないため、先に完成させる。**

### 4.1 脱落曲線の生成
作品ごとに、離脱したユーザーの `watched_episodes` のヒストグラムを算出。

出力（作品ごと）:
```json
{
  "anime_id": 11061,
  "dropout_curve": [
    {"episode": 1, "rate": 0.04},
    {"episode": 3, "rate": 0.19}
  ],
  "peak_dropout_episode": 3,
  "survival_after_peak": 0.84,
  "population_completion_rate": 0.74
}
```
`survival_after_peak` = ピーク話数を超えて視聴した人のうち、完走した割合。

**サンプル数が少ない作品は信頼できない。離脱者50件未満の作品はカーブを出力せず、`insufficient_data: true` を返す。**

### 4.2 質問候補リストの生成
手動入力画面に表示する作品を選定する。

選定基準（優先度順）:
1. 登録者数が十分（上位N件）
2. **完走率が0.5付近**（回答が割れる = 情報量が最大）
3. ジャンル・年代・話数が分散するよう調整

出力: `data/question_pool.json`（150〜300本程度）
各要素に title, anime_id, year, episodes, genres, completion_rate, split_score を含める。

`split_score` は情報量の指標。エントロピー等で算出し、デフォルトのソート順に使う。

### 4.3 ユーザープロファイル算出ロジック
入力（完走/好き/途中で止まった）から以下を算出する純粋関数として実装:

| 項目 | 算出方法 |
|---|---|
| 話数レンジ別完走率 | 話数を4バケット（〜13/14〜26/27〜50/51話〜）に分け、バケットごとの完走率と本数を算出。本数3本未満のバケットは「データ不足」とし判定から除外する。「合う話数」＝本数3本以上のバケットのうち完走率が最も高いもの（旧・耐久話数「完走率が50%を切る話数」は長編を完走したユーザーで外れ値化するため2026-08修正で廃止。ただし予測モデルの`episode_gap`特徴量は学習時の定義との整合のため旧定義のまま維持） |
| 完走率 | 完走数 / (完走数 + 離脱数) |
| 好むジャンル | 完走作品のジャンル出現率 − 全体平均 の上位 |
| 避けるジャンル | 同下位 |
| 話題作追従度 | 回答した作品の登録者数分布 |
| タイプ名 | 話数レンジ別完走率の「合う話数」(短/中/長) × 好みの軸 の組み合わせで機械生成 |

**タイプ名にネガティブな語を使わないこと**（「飽きっぽい」「脱落型」等は禁止）。

## 5. Phase 2: 予測モデル

### 5.1 タスク定義
二値分類。目的変数 = 完走(1) / 離脱(0)。`watching`, `plan to watch`, `on hold` は原則除外（Phase 0 チェック③の結論に従う）。

### 5.2 データ分割【リーク防止・厳守】
- **必ず user_id 単位で分割する。** 作品単位で分割すると同一ユーザーが訓練とテストに跨り、リークする
- 訓練 70% / 検証 15% / テスト 15%
- **作品の平均完走率を特徴量に使う場合、訓練ユーザーのみから算出すること**

### 5.3 入力制限のシミュレーション【重要】
実ユーザーは20本程度しか回答しない。訓練・評価時も同条件にする。

```
各テストユーザーについて:
  1. question_pool に含まれる作品のうち、そのユーザーが回答している行だけを抽出
  2. そこから最大 N 本をサンプリング（N = 5, 10, 20, 30 で実験）
  3. それをプロファイル生成の入力とする
  4. 残りの作品の完走/離脱を予測させ、評価する
```

### 5.4 特徴量

**作品側**
- 総話数、ジャンル（multi-hot）、スタジオ、原作媒体、放送年、登録者数(log)、MALスコア
- 作品の平均完走率（訓練ユーザーのみから算出）
- あらすじの埋め込み（multilingual-e5-small）

**ユーザー側**
- 耐久話数、完走率、ジャンル別完走率
- 完走作品の埋め込み平均（= 完走ベクトル）
- 離脱作品の埋め込み平均（= 離脱ベクトル）

**交互作用【本命】**
- `cos(候補作品, 完走ベクトル)`
- `cos(候補作品, 離脱ベクトル)` ← ネガティブ情報
- **話数バケット完走率・話数バケットギャップ**（旧: 話数ギャップ = 候補作品の話数 − ユーザーの
  耐久話数）。旧定義はテストユーザーN=20時点で中央値175話・100話超54.3%と外れ値の影響が
  大きいことが判明したため、2026-08に話数レンジ4バケットベースの
  `episode_bucket_completion_rate` / `episode_bucket_gap` へ置き換えて再学習した
  （AUC -0.0003 / PR-AUC +0.0020、詳細は `reports/retrain_episode_bucket.md`）
- 候補作品のジャンルにおけるユーザーの完走率
- 人気度とユーザー嗜好の乖離

### 5.5 モデル
LightGBM をベースラインとする。まず特徴量の質で戦い、モデルの複雑化は後回しにする。

### 5.6 評価要件【必ずこの表を出力すること】

```
                                        AUC     PR-AUC
ランダム                                0.50
人気順（登録者数）                       ?
作品の平均完走率のみ                     ?
 + ユーザー特徴（耐久話数・ジャンル）      ?
 + 埋め込み類似度（完走ベクトルのみ）      ?
 + 離脱ベクトル                          ?      ← ネガティブ情報の寄与
```

**評価指標は AUC / PR-AUC を使う。Accuracy は使わない**（クラス不均衡のため「全部完走」で高得点が出る）。

### 5.7 追加で必ず出力する分析

#### ① 入力本数 × 精度の曲線
```
入力 3本 → AUC ?
入力 5本 → AUC ?
入力10本 → AUC ?
入力20本 → AUC ?
入力30本 → AUC ?
```
どこで頭打ちになるかを可視化。UI設計の根拠になる。

#### ② 入力種別ごとの寄与
```
「好き」のみ              AUC ?
 + 「完走」               AUC ?
 + 「途中で止まった」      AUC ?
```
3種類に分ける設計が正当化されるかを検証。差がなければ設計を簡略化する。

#### ③ 人気順との推薦重複
人気順トップ20 と 個人最適トップ20 の重複件数。**これがサービスの主張そのもの。**

#### ④ 上限の見積もり
離脱のうち、好み以外の要因（多忙・失念等）による割合を推定し、理論上限を議論すること。
達成AUCを「上限からの達成率」として記述する。

### 5.8 期待される精度（参考値・保証ではない）
- 作品平均完走率のみ: 0.70〜0.75
- フルモデル: 0.76〜0.82
- 個人化による上乗せは +0.05〜0.08 程度が現実的

**この数値を下回っても直ちに失敗ではない。上限の議論とセットで報告すること。**

## 6. Phase 3: API（FastAPI）

### 6.1 `GET /questions`
質問候補リストを返す。

クエリパラメータ:
- `q`: タイトル検索（部分一致）
- `genre`, `year_from`, `year_to`, `episodes_max`
- `sort`: `split_score`（デフォルト） | `popularity` | `year` | `low_completion`
- `limit`, `offset`

`sort=low_completion` は完走率が低い作品を並べる。「途中で止まった作品を思い出せない」問題への対策。

### 6.2 `POST /predict`
```json
{
  "responses": [
    {"anime_id": 9253, "label": "loved"},
    {"anime_id": 5114, "label": "completed"},
    {"anime_id": 6547, "label": "dropped"}
  ]
}
```
label は `loved` | `completed` | `dropped` の3値のみ。未回答は送らない。

レスポンス:
```json
{
  "profile": {
    "type_name": "短距離・重量級タイプ",
    "endurance_episodes": 12,
    "completion_rate": 0.58,
    "completion_rate_avg": 0.71,
    "preferred_genres": ["Sci-Fi", "Psychological"],
    "avoided_genres": ["Slice of Life"],
    "curve": [
      {"episodes": 12, "user": 0.82, "avg": 0.78},
      {"episodes": 24, "user": 0.31, "avg": 0.66}
    ]
  },
  "at_risk": [
    {
      "anime_id": 11061,
      "title": "...",
      "completion_prob": 0.26,
      "popularity_rank": 3,
      "reasons": [
        {"type": "episode_gap", "text": "全50話（完走実績の最長は26話）"},
        {"type": "similarity", "text": "途中で止まった『◯◯』と傾向が近い"},
        {"type": "genre", "text": "日常系の完走率は21%"}
      ]
    }
  ],
  "will_complete": [ ... ],
  "baseline_comparison": {
    "popular_top20": [...],
    "personalized_top20": [...],
    "overlap": 4
  }
}
```

**`reasons` は必ず3件程度返す。確率だけでは信用されない。**

### 6.3 `POST /predict/single`【最重要エンドポイント】
特定作品1本に対する判定。ユーザーが繰り返し使う機能。

```json
{
  "responses": [...],
  "target_anime_id": 11061
}
```

レスポンス:
```json
{
  "anime": {"title": "...", "episodes": 50, "genres": [...], "year": 2013},
  "completion_prob": 0.31,
  "population_completion_rate": 0.74,
  "confidence": "high",
  "is_estimated": false,
  "factors": {
    "negative": [{"type": "episode_gap", "text": "..."}],
    "positive": [{"type": "genre", "text": "..."}]
  },
  "evidence": [
    {"title": "AAA", "episodes": 50, "genre": "日常", "result": "dropped"},
    {"title": "CCC", "episodes": 50, "genre": "SF", "result": "completed"}
  ],
  "evidence_insight": "話数より「日常系」が効いていそうです",
  "dropout_curve": [{"episode": 1, "rate": 0.04}],
  "peak_dropout_episode": 3,
  "survival_after_peak": 0.84,
  "advice": "まず3話まで。越えられれば完走の可能性が高いです"
}
```

**`evidence` はユーザー自身の過去の回答から、条件が近いものを抽出して返す。** 予測根拠として最も説得力がある。

`confidence` は `high` | `medium` | `low`。判定に使えた類似作品数、脱落曲線のサンプル数などから決定する。

`is_estimated: true` は2021年以降の作品（内容ベースのみで推定）。UIで明示すること。

### 6.4 `POST /feedback`（Phase 5・後回し可）
```json
{"session_id": "...", "anime_id": 11061, "result": "completed"}
```
出口ラベルの回収。**テーブル設計だけは最初に行い、後から追加しやすくしておくこと。**

## 7. Phase 4: フロントエンド（React）

### 7.1 入力画面
- 上部固定: 検索窓 + 絞り込み（年代 / ジャンル / 話数 / 並び替え）
- 進捗表示: 回答済み本数と、それに応じた精度の目安
- 各作品カード: `[♥ 好き] [✓ 完走] [⏸ 途中で止まった]` の3ボタン
- **「見てない」ボタンは置かない。** 未回答は何も押さないだけ
- デフォルトのソートは `split_score` 順
- 「完走率が低い作品」タブを用意する

### 7.2 結果画面（この順序で配置）

1. **単体判定の入力欄**（最上部固定）— 「この作品、あなたは完走できる?」
2. **タイプ診断カード** — シェアされる想定。視覚重視
3. **話題作だけど続かないかも** — 本体。各作品に理由3行を必ず表示
4. **完走できる作品**
5. **脱落曲線グラフ** — 個人曲線と全体平均を重ねて描画
6. **人気順との比較** — 主張の証明

### 7.3 表示上の必須ルール
- 確率は必ず「完走率○%」で表示。離脱確率を表示しない
- 判定結果には「作品の評価ではなく、あなたとの相性の話です」を明記
- `is_estimated: true` の場合は推定である旨をUI上で明示
- `confidence` を必ず表示する
- タイプ名・診断文にネガティブな断定を含めない

- 作品単位でのデータ分割（リーク）
- 全データから算出した作品平均完走率を特徴量に使う（リーク）

- Accuracy による評価
- 履歴フル使用での精度を、実サービスの精度として報告すること
- UI上で「切る」という表現を使うこと
- 「絶対に完走できます」等の断定表現
- MALの作品画像を直リンクすること
