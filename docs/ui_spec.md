# UI仕様書 — 入力画面 / 出力画面

本書は要件定義書 Phase 4 の詳細仕様。実装時はこちらを優先する。

---

## 0. 設計原則

### 0.1 入力負荷の原則
**ユーザーに数十本の回答を要求してはならない。**

- 結果表示の最低ライン: **5本**
- 推奨: 10本
- それ以上は任意。強制しない
- 未回答はボタンを押さない = スキップ。「見てない」ボタンは作らない

段階的に結果を解放する（プログレッシブ・ディスクロージャー）。フォームを完成させてから結果を出す設計にしない。

### 0.2 用語規約（再掲・厳守）
- UI上で「切る」「切った」「脱落」「ドロップ」を使わない
- 確率は必ず「完走率○%」で統一。離脱確率を表示しない
- 断定表現を使わない（「絶対に完走できます」等）

### 0.3 レスポンシブ
モバイルファースト。基準幅 375px。デスクトップは中央寄せ最大 720px。

## 1. 画面フロー

```
[A] ランディング
      ↓
[B] 入力画面 ←──────────┐
      ↓ (5本以上)        │
[C] 結果画面              │ 「回答を追加」
      ├─ [D] 単体判定 ────┘
      └─ [E] フィードバック
```

結果画面から入力画面へ**いつでも戻れる**こと。戻った際、既存の回答は保持される。

```
┌──────────────────────────────────────┐

│ │ 🔍 [ タイトルを検索          ]   │  │

│ │                                   │  │
│ │ 3本回答  ━━━░░░░░░  あと2本で結果 │  │
│ └───────────────────────────────────┘  │
│                                        │
│  ┌────────────────────────────────┐   │
│  │ STEINS;GATE                     │   │
│  │ 2011 / 全24話 / SF・サスペンス   │   │
│  │                                  │   │
│  │ [ ♥ 好き ][ ✓ 完走 ][ ⏸ 途中で ]│   │
│  └────────────────────────────────┘   │
│                                        │

│  │ けいおん!                        │   │

│  │                                  │   │

└──────────────────────────────────────┘
```

### 3.2 作品カード

**表示項目**
| 項目 | 必須 | 備考 |
|---|---|---|
| タイトル（日本語） | ○ | 長い場合は2行まで、以降省略 |
| 放送年 | ○ | |
| 総話数 | ○ | 「全24話」形式 |
| ジャンル | ○ | 最大2つまで |
| 画像 | ✕ | **MALの画像を直リンクしない。使用しない** |

**ボタン**
```
[ ♥ 好き ]  [ ✓ 完走 ]  [ ⏸ 途中で止まった ]
```
- 3つは**排他選択**（ラジオボタン的挙動）
- 「好き」は「完走」を内包する（好き = 完走 + 高評価）
- モバイルではボタン文言を短縮可: `♥好き` / `✓完走` / `⏸途中`
- タップ領域は最低 44×44px

**状態**
| 状態 | 表示 |
|---|---|
| 未回答 | 3ボタンとも枠線のみ |
| 選択済み | 選択したボタンを塗りつぶし、カード全体に淡い背景色 |
| 再タップ | 同じボタンを再度押すと選択解除 |

**アニメーション**
- 回答時、カードが軽く沈む程度。**カードを消さない**。押し間違いの修正ができなくなるため

### 3.3 検索

```
🔍 [ タイトルを検索 ]
```
- 入力2文字以上でインクリメンタル検索（300msデバウンス）
- 部分一致。ひらがな/カタカナ/英字を正規化して照合すること
- **question_pool 外の作品もヒットさせる。** ユーザーは自分が見た作品を探しに来る
  - pool 外の作品も回答可能とする（プロファイル生成には使える）
- 検索結果0件: 「該当する作品が見つかりませんでした。2020年までの作品が対象です。」

### 3.4 絞り込み

| フィルタ | 選択肢 |
|---|---|
| 年代 | 〜2005 / 2006-2010 / 2011-2015 / 2016-2020 |
| ジャンル | anime.csv のジャンルから主要20件（複数選択可） |
| 話数 | 〜13話 / 14〜26話 / 27話〜 |

- 適用中のフィルタはチップとして表示し、個別に×で解除できること
- 「すべてクリア」を用意

### 3.5 並び替え

| 値 | 表示名 | 用途 |
|---|---|---|
| `split_score` | **おすすめ順**（デフォルト） | 回答が割れる作品＝情報量最大 |
| `popularity` | 人気順 | 王道から答えたい人 |
| `low_completion` | **完走率が低い順** | 「途中で止まった作品」の想起支援 |
| `year_desc` | 新しい順 | |

**`low_completion` は専用タブとして目立たせる。**
```
[ おすすめ ] [ 人気 ] [ 途中で止まりやすい作品 ]
```
理由: 人は途中で止めた作品を覚えていない。想起ではなく**再認**にする必要がある。一覧に並べれば「あ、これ止まってた」と思い出せる。

このタブの上部に説明を置く:
> 途中で止まった作品は思い出しにくいもの。よく止まる作品を並べました。

### 3.6 進捗表示

```
3本回答  ━━━░░░░░░  あと2本で結果が見られます
```

| 回答数 | 表示 |
|---|---|
| 0 | 「気になる作品から答えてみてください」 |
| 1-4 | 「あと○本で結果が見られます」 |
| 5-9 | 「結果を見られます。10本で精度が上がります」 |
| 10-19 | 「精度：中。20本でさらに上がります」 |
| 20+ | 「精度：高。十分です」 |

**20本を超えたら追加を促さない。** これ以上は精度がほぼ変わらないため、要求すると信頼を失う。

### 3.7 フッターCTA
- 4本以下: 非表示（またはグレーアウト）
- 5本以上: `[ 結果を見る（5本） ]` を固定表示
- 結果画面から戻ってきた場合: `[ 結果を更新（12本） ]`

### 3.8 状態保持
- 回答は localStorage に保持し、リロードで消えないこと
- 結果画面との往復で消えないこと

### 3.9 リセットボタン
- 配置: 進捗表示（3.6）の右端。絞り込みバー（3.4）の右端でもよい
- 回答が0件のときは非表示（または無効化）
- 押すと確認ダイアログを表示する:
  「回答をすべて解除しますか？」に対し「解除する」「キャンセル」の2択
  （誤タップで全回答が消えると体験が最悪になるため、即時実行しない）
- 「解除する」を選ぶと、画面上の選択状態に加えて localStorage 上の回答も削除する

## 4. [C] 結果画面

### 4.1 ブロック配置順（この順序を厳守）

```
1. 単体判定の入力欄     ← 最上部・固定
2. タイプ診断カード
3. 話題作だけど続かないかも  ← 本体
4. 完走できる作品
5. 脱落曲線グラフ
6. 人気順との比較
7. 回答を追加するCTA
```

**1を最上部に置く理由**: 診断は1回で終わるが、単体判定は何度でも使う。リピート動線を最上部に固定する。

### 4.2 信頼度バナー（回答5-9本のとき）

```
┌──────────────────────────────────┐
│ ⓘ 回答5本のため、精度は控えめです  │
│   10本まで増やすと精度が上がります │
│   [ 回答を追加する ]               │
└──────────────────────────────────┘
```
10本以上では非表示。

### 4.3 ブロック1: 単体判定入力

```
┌──────────────────────────────────────┐
│  この作品、あなたは完走できる？        │
│  [ タイトルを入力            ] [判定] │
└──────────────────────────────────────┘
```
- sticky で画面上部に固定
- オートコンプリート付き
- 判定結果は [D] のモーダルまたは展開パネルで表示

### 4.4 ブロック2: タイプ診断カード

```
┌──────────────────────────────────────┐
│                                       │
│         短距離・重量級タイプ           │
│                                       │
│   1クールなら完走できるが、2クール    │
│   以上は最後まで届きにくい。重い      │
│   テーマを好み、日常系は最初から      │
│   手を出さない傾向。                  │
│                                       │
│   ┌─────────┬─────────┐              │
│   │  合う    │  完走率  │              │
│   │  話数     │          │              │
│   │ 14〜26話  │   58%    │              │
│   │          │(全作品平均71%)│           │
│   └─────────┴─────────┘              │
│                                       │
│   話数レンジ別の完走率                 │
│   〜13話 14〜26話 27〜50話 51話〜       │
│   データ不足 [58%]  35%    データ不足  │
│                                       │
│   好む傾向    SF / 心理 / シリアス     │
│   避ける傾向  日常 / 部活              │
│                                       │
│              [ 画像で保存 ]           │
└──────────────────────────────────────┘
```

**「合う話数」の算出（2026-08修正）**
話数を4バケット（〜13話 / 14〜26話 / 27〜50話 / 51話〜）に分け、バケットごとに完走率と本数を集計する。
本数3本未満のバケットは「データ不足」として判定から除外し、残ったバケットのうち完走率が
最も高いものを「合う話数」とする。旧版の「完走率が50%を切る話数」という単一の数値指標は、
長編を1本でも完走したユーザーで外れ値（数百話）に張り付き、表示として意味をなさなかったため廃止した。

**タイプ名の生成規則**
- 「合う話数」のバケット（短距離=〜13話 / 中距離=14〜26話 / 長距離=27話〜）× 好みの軸 の組み合わせで機械生成
- **ネガティブな語を使わない**
  - ✕ 飽きっぽいタイプ / 脱落型 / 根気なしタイプ
  - ○ 短距離型 / 一気見型 / 積み上げ型 / 完走職人 / 選球眼タイプ
- 完走率が低いことは「選ぶ基準が厳しい」と表現してよい（同じ数字の別の見方であり、歪曲ではない）

**[画像で保存]** はシェア導線。実装優先度は中。

### 4.5 ブロック3: 話題作だけど続かないかも【本体】

```
┌──────────────────────────────────────┐
│  話題作だけど、あなたには続かないかも  │
│                                       │
│  ┌─────────────────────────────────┐ │
│  │ □□□□□□                          │ │
│  │ 2013 / 全50話 / 日常・部活        │ │
│  │ MAL人気ランキング 3位             │ │
│  │                                    │ │
│  │      あなたの完走率  78%           │ │
│  │      ━━━━━━━━━━━━━━░░░           │ │
│  │      一般平均 94%                  │ │
│  │                                    │ │
│  │ ▼ 続きにくい理由                   │ │
│  │  ・全50話。あなたが完走できている  │ │
│  │    のは平均12話まで                │ │
│  │  ・途中で止まった『◯◯』と傾向が   │ │
│  │    近い                            │ │
│  │  ・日常系はあなたの完走率が21%     │ │
│  └─────────────────────────────────┘ │
│                                       │
│  （同形式でさらに4件）                 │
│                                       │
│  ※ 作品の評価ではなく、あなたとの     │
│    相性の話です                       │
└──────────────────────────────────────┘
```

**必須要件**
- **理由を必ず3件表示する。** 確率だけでは信用されない
- 理由は API の `reasons` をそのまま表示。フロントで文言生成しない
- 末尾の注記「作品の評価ではなく〜」は**必ず表示**。名作を貶しているという誤解を防ぐ
- 表示は5件まで

**at_risk が0件の場合**
`at_risk` 配列が空（該当作品なし）の場合、ブロックごと非表示にはせず、以下の文言を表示する:
```
今回の候補には、あなたが特に止まりやすそうな作品は
ありませんでした
```
これはユーザーにとって好ましい結果であり、機能が壊れているわけではないことを明示する。

### 4.6 ブロック4: 完走できる作品

```
┌──────────────────────────────────────┐
│  あなたが最後まで見られそうな作品      │
│                                       │
│  1. ◯◯◯◯      完走率 89%（一般70%）  │
│     2011 / 全12話 / SF                │
│     └ 一般には完走されにくいですが、  │
│       あなたの傾向なら見切れそうです  │
│                                       │
│  2. ...                               │
└──────────────────────────────────────┘
```
- 10件表示
- 理由は1行でよい（ブロック3ほど詳細でなくてよい）。理由はAPIの`reason`をそのまま表示し、
  フロントで文言生成しない
- 予測完走率（`completion_prob`）と母集団完走率（`population_completion_rate`）を
  **両方表示する**。予測完走率だけでは「もともと誰でも完走できる作品」なのか
  「あなたの傾向だから完走できる作品」なのかが伝わらないため

**候補選定ロジック（2026-08修正）**

予測完走率（`completion_prob`）の降順だけでソートすると、1話の映画・OVA（定義上ほぼ100%
完走）が上位を独占し、推薦として意味をなさなくなる問題が判明した。以下のように修正した。

1. **候補フィルタ**: Type（Movie/Music/Special）・総話数（6話以下）・登録者数
   （50,000未満）・MALスコア（7.0未満）で候補から除外する
2. **ソート基準**: `relative_completion = 予測完走率 / 母集団完走率` の降順に変更した
   （`relative_completion` としてレスポンスに含まれる）。at_riskの`relative_risk`と
   対称の設計。「一般的には完走率が低いが、あなたの傾向なら完走しやすい」作品を上位に
   引き上げる
3. **話数バケット連動**: 候補をユーザーの「合う話数」バケット、またはその1つ上の
   バケットに属する作品に限定し、診断結果（ブロック2）と推薦を連動させる。該当作品が
   10件に満たない場合のみ隣接バケットまで広げる
4. **多様性の確保**: 上位10件が同一ジャンルに偏らないよう、主ジャンルごとの上限を
   3件とする貪欲法で選定する

## 5. [D] 単体判定画面

### 5.1 レイアウト（既存作品・データ十分の場合）

**設計方針（改訂）**: 登録者数上位1,000作品では完走率80%未満が3.5%しかなく（実測）、
有名作の絶対値はほとんどが90%超に密集する。絶対値だけでは作品間の差が伝わらないため、
**相対指標（`relative_risk`＝一般平均に対して何倍止まりやすいか）を主表示**とし、
完走率の絶対値は副表示に回す。確率としては完走率のみを使い、離脱確率は表示しない
（`relative_risk`は完走率から導出した副次指標であり、離脱確率の直接表示ではない）。

```
┌──────────────────────────────────────┐
│ □□□□□□                       [×]  │
│ 2013 / 全50話 / 日常・部活            │
├──────────────────────────────────────┤
│                                       │
│     平均より 2.7倍 止まりやすい       │
│                                       │
│        完走率 84%（一般平均94%）      │
```

### 5.2 判定文言の閾値（改訂）

実測の予測完走率分布（テストユーザーの「最も危険な1本」の分布: 最小4.9% / 25%点70.5% /
中央値85.4% / 75%点92.3%）を踏まえ、しきい値を高い側に再較正した。

| 完走率 | 文言 |
|---|---|
| 95%以上 | ✓ 問題なく見られそうです |
| 88-94% | ✓ 完走できそうです |
| 75-87% | 〜 やや注意。平均より止まりやすい傾向 |
| 50-74% | ⚠ 完走は難しいかもしれません |
| 50%未満 | ⚠ 最後まで届きにくいかもしれません |

旧版の「五分五分です」（40-59%）は削除した。実測では完走率75%程度の作品でも一般平均
（94%前後）と比べれば明確に「止まりやすい」側であり、これを「五分五分」と表現するのは
実態と乖離するため。

**断定しない。すべて推量形で書く。**

### 5.3 「あなたの実績」ブロック【重要】

ユーザー自身の過去の回答から、条件が近い作品を3件抽出して表示する。

**これが最も説得力のある根拠。** 確率だけでは信用されないが、自分の過去の行動を並べられると納得度が跳ね上がる。

`evidence_insight`（「話数より日常系が効いていそうです」）も API から受け取って表示する。モデルが何を根拠にしたかが伝わる。

該当作品が0件の場合はブロックごと非表示。

### 5.4 脱落曲線ブロック

- `insufficient_data: true`（離脱者50件未満）の場合はブロック非表示、代わりに以下を表示
  ```
  📉 この作品はデータが少なく、
     止まりやすい話数を表示できません
  ```
- `advice` は API から受け取った文字列をそのまま表示

### 5.5 完走率が高い場合の追加表示

判定が80%以上のとき、情報量が乏しくなるため次の導線を出す。

```
  ✓ 問題なく見られそうです

  ─────────────────────────
  この作品を完走した人のうち、
  あなたと傾向が近い層が次に完走している作品

   DDDD   あなたの完走率 87%
   EEEE   あなたの完走率 82%
```

### 5.6 新作（2021年以降）の場合

```
┌──────────────────────────────────────┐
│ 新作タイトル                          │
│ 2025 / 全24話 / SF                    │
├──────────────────────────────────────┤
│        あなたの完走率                 │
│           推定 72%                    │
│                                       │
│   ⓘ 2021年以降の作品のため、内容の    │
│     傾向から推定しています            │
│     信頼度：低                        │
├──────────────────────────────────────┤
│ ▼ 判定に使った情報                    │
│  ・全24話（あなたの耐久12話をやや超過）│
│  ・SF・心理（あなたの完走率が高い領域）│
│  ・あらすじの傾向が『◯◯』（完走済み） │
│    に近い                              │

│    データがないため表示できません      │
└──────────────────────────────────────┘
```

**推定であることを隠さない。** `is_estimated: true` のとき、数値の前に「推定」を必ず付ける。

### 5.6b 放送継続中の作品の場合

放送が完結していない作品は、視聴を継続しているファンのほとんどが「視聴中」のまま
決着しておらず、実績データ上の完走率が実態を反映しない（右側打ち切り）。この場合
`is_ongoing: true` が返る。`is_estimated` と同様に扱い、数値の前に「推定」を付け、
信頼度は必ず「低」にする。

```
┌──────────────────────────────────────┐
│ 放送中タイトル                        │
│ 2020 / 全24話（放送中）/ 少年          │
├──────────────────────────────────────┤
│        あなたの完走率                 │
│           推定 68%                    │
│                                       │
│   ⓘ 放送中の作品のため、完走データが  │
│     不足しています。内容の傾向から    │
│     推定しています                    │
│     信頼度：低                        │
├──────────────────────────────────────┤
│ 📉 止まりやすい話数                    │
│    データがないため表示できません      │
└──────────────────────────────────────┘
```

`is_estimated`（2021年以降の新作）と `is_ongoing`（放送継続中）は原因が異なるため
別フィールドとして返るが、UI上の扱い（「推定」表示・信頼度「低」固定）は共通でよい。
文言のみ出し分ける。

### 5.7 信頼度バッジ

| confidence | 表示 | 色 |
|---|---|---|
| high | 信頼度：高 | 通常 |
| medium | 信頼度：中 | 通常 |
| low | 信頼度：低 | 注意色 |

**必ず表示する。** 精度が出ない部分を隠さず表示することが、ミスマッチを扱うサービスとして誠実な形。

## 9. 禁止事項（再掲）

- UI上で「切る」「切った」「脱落」「ドロップ」を使う
- 離脱確率を表示する（完走率に統一）
- 断定表現（「絶対に完走できます」等）
- MALの作品画像を直リンクする
- 20本を超えた回答を促す
- 5本未満で結果を出す
- 回答するとカードが消える挙動
- タイプ名にネガティブな語を使う
- `is_estimated` / `confidence` を非表示にする
