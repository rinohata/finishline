# デザインガイドライン

FinishLineの見た目を「診断コンテンツ寄り・カラフル・シェアしたくなる」方向へ刷新するための
指針。トークンの実体は `frontend/src/styles/tokens.css`。

## 大前提: パッケージはカラフルに、数字は硬派に

本サービスの価値は32万人の実データに基づく予測であり、占いに見えた瞬間に価値が損なわれる。
そのため以下の二層で明確に線引きする。

| | パッケージ（カード・配色・タイポの装飾） | 数字（完走率・倍率・脱落曲線） |
|---|---|---|
| 方針 | カラフル・丸み・グラデーション可 | 硬派・装飾なし |
| フォント | M PLUS 1p（丸みのある日本語） | Inter（tabular-nums、ラテン数字） |
| 色 | プライマリブルー・注意色・成功色を積極的に使う | `--fl-color-text`（濃紺グレー）固定。意味的な色（注意/成功）以外で数字自体を彩色しない |
| 背景 | グラデーション・淡色タイントOK | **数値の直接の背景にグラデーションを使わない** |
| 装飾 | アイコン・角丸・影OK | **数字自体を装飾書体にしない・斜体にしない** |
| 絵文字 | セクション見出し等での使用は絞って許容 | **数字の隣に絵文字を置かない** |

この4つの禁止事項（数値背景グラデーション禁止／数値装飾書体禁止／数値隣接絵文字禁止／
情報量を削らない）は今回のリニューアル全体を通しての固定ルールとする。

`docs/ui_spec.md` 9章の禁止事項（「切る」「切った」「脱落」「ドロップ」を出さない、
断定表現をしない、5本未満で結果を出さない、20本超で追加を促さない、MAL画像を直リンクしない）は
デザイン刷新後も全て維持する。

## カラー

`--fl-color-*`（`tokens.css`）。

| トークン | 値 | 用途 |
|---|---|---|
| `--fl-color-primary` | `#2563eb` | プライマリボタン・強調・グラフの個人曲線など |
| `--fl-color-primary-dark` | `#1d4ed8` | hover・押下状態 |
| `--fl-color-primary-tint` | `#eaf1fe` | カード背景の淡いブルー装飾 |
| `--fl-color-warning` | `#f59e0b` | **at_risk（続きにくい予測）**。エラーではなく注意の意味なので橙寄りにし、赤は使わない |
| `--fl-color-success` | `#16a34a` | will_complete（完走できそうな作品）などポジティブな文脈 |
| `--fl-color-bg` | `#f4f7fc` | 画面全体の背景。ブルーを僅かに含んだニュートラル |
| `--fl-color-surface` | `#ffffff` | カード・入力欄の背景 |
| `--fl-color-text` / `-secondary` / `-muted` | `#14203b` / `#47536b` / `#7c869b` | テキストの主・副・淡。地の色にも寒色を僅かに含め、ブルー基調と統一感を持たせる |

**at_riskの色について**: 従来 `--color-accent: #d9534f`（赤）を警告・強調の両方に流用していたが、
今回 `--fl-color-warning`（橙）に分離した。作品を「悪い」と否定しているわけではなく、
「あなたには合わないかもしれない」という注意喚起なので、エラー色（赤）ではなく注意色（橙）を使う。

## タイポグラフィ

### フォント選定理由

- **日本語（見出し・本文・UI文言）: M PLUS 1p**
  候補として Noto Sans JP・Zen Kaku Gothic New・M PLUS 1p を比較した。Noto Sans JPは
  可読性・収録字形ともに堅実だが、あらゆるサービスで使われておりテンプレート感が強い。
  Zen Kaku Gothic Newは幾何学的で現代的だが硬さがあり、診断コンテンツの親しみやすさには
  やや欠ける。M PLUS 1pは角に丸みがあり親しみやすい一方、子供っぽくなりすぎない
  ウェイト設計（400〜800）を持ち、LINE系サービスなど日本の消費者向けアプリ・診断/クイズ
  コンテンツで広く使われている実績がある。「一般ユーザーが専門知識なしで楽しめる」
  「シェアしたくなる」という要件に最も合致するため採用した。
- **数値専用: Inter**
  完走率・倍率・話数など「事実として硬派に見せたい数字」はすべてInterを使う。
  tabular-nums（等幅数字）機能を持ち、桁が変わってもレイアウトが揺れない。Stripe・Linear等
  データ系プロダクトで定番の書体で、M PLUS 1pの柔らかい本文との対比により、パッケージの
  カラフルさとは独立して数字の信頼性を視覚的に担保する役割を持たせている。
  **数値を表示する箇所は必ず `.fl-numeric` クラス（`font-variant-numeric: tabular-nums`）
  を通すこと。**

## 絵文字の扱い

現状 ⚠（at_risk・単体判定の警告）・📉（脱落曲線見出し）・♥✓⏸（回答ボタン）・🔍（検索）が
各所に散在している。方針:

- **数字に隣接する絵文字は使わない**（例: 完走率の数字の横に⚠を置かない）
- 状態を表す⚠・📉は、置き換え可能な箇所からSVGアイコン（線画・単色、`--fl-color-warning`等の
  トークンで着色）に順次置き換える。置き換えが今回のスコープ外の画面では、使用箇所を
  絞る（1画面に同じ絵文字を繰り返し出さない）ことで対応する
- 回答ボタンの♥✓⏸や検索の🔍のように、意味を一目で伝えるUIパーツとしての絵文字は
  過度な多用でなければ許容する（絵文字の全廃ではなく「数字の隣に置かない」「装飾として
  使わない」ことが本質）

具体的な置き換えは各コンポーネントの移行時に行う（本ドキュメント自体では実施しない）。

## 段階的適用の方針

新トークンは `frontend/src/styles/tokens.css` に `--fl-` プレフィックスで定義し、
既存の `index.css` の `--color-*` とは名前空間を分離している。理由: 値を更新した瞬間に
未移行の画面まで巻き添えで見た目が変わるのを防ぎ、コンポーネント単位で確実に移行するため。

適用順序と状態:

1. ✅ トークン定義・本ガイドライン（今回）
2. ✅ タイプ診断カード（`TypeDiagnosisCard.tsx`。シェアされる主役のため最優先）
3. ⬜ 結果ページ全体
4. ⬜ 入力ページ
5. ⬜ ランディングページ

各画面の移行が完了するたびに、その画面内の `var(--color-*)` 参照を `var(--fl-color-*)` に
置き換える。全画面の移行が終わったら、`index.css` の旧トークン定義を削除し
`tokens.css` に一本化する。
